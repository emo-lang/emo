# `var` 逃逸规则

Emo 的 Syntax 一节规定:`var` 绑定是块作用域的,把这样一个绑定捕获进可能比它的块活得更久的闭包,是编译错误。本文记录编译器(步骤 09,`emo_check`)如何判定一次捕获是否构成错误。

## 实际实现的规则

检查器的流式环境为每个绑定跟踪两项信息:

- `depth`——引入该绑定的块的嵌套深度(程序是深度 0;每个 `if` / `case` / 箭头块体都深一层);
- `block_depth`——最内层外围箭头块被*书写*时的深度(不在任何箭头块内时缺席,为 `-1`)。

对 `var` 的引用出现在一个箭头块内,而该箭头块的定义深度大于引入这个 `var` 的块的深度时,就是编译错误(**E4012**):

```emo
def probe(flag Bool) Int64 {
  if flag {
    var x = 1
    if flag {
      const g = -> {
        return x      // error[E4012]: the var `x` cannot be captured ...
      }
      return g()
    }
  }
  return 0
}
```

## 这一近似,以及它抓不到的东西

这是计划中要求的、保守但简单的近似,不是借用检查器:

- `var` 与箭头块在*同一个*块里时是接受的(`var x = 1` 紧挨着 `const g = -> { return x }`),即使 `g` 原则上可能被返回。检查器不跟踪块值是否逃逸。
- 从与箭头块相同深度捕获的 `var` 同样接受。

因此实际实现的规则比 README 中最坏情况的读法更窄:它只拒绝那些 `var` 的块可以证明包围了箭头块定义处的捕获——也就是闭包按构造必然比变量活得久的形状。其余情况交给运行时纪律(`Box` 是长期可变状态的既定载体)。

## 为什么 `Box` 不受影响

`Box` 值是不可变引用;把绑定到 `Box` 的 `const` 捕获进任何闭包都总是可靠的,这正是 README 把 `Box` 指为闭包持有长期可变状态之方式的原因。
