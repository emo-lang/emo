# 协议（Protocols）

Emo 的元编程是一个小而封闭的**语言协议**注册表：语言在其上进行分派的具名方法，拼写平常，由编译器强制执行。协议方法没有任何标记性的前后缀——承载这个区分的是注册表，而且编译器在两端都把它说清楚：签名不对的定义是编译错误，对没有该方法的类型走注册表调用，在类型可知处同样是编译错误。

这属于显式协议这一派：语言的泛型操作是有文档名字的普通方法，而语言明说自己在哪些名字上分派。魔法式元编程——缺方法钩子、运行时定义方法、打开类——不是 Emo 选择不实现的某种变体；声明形状让它根本不可能，因为类的方法集恰好就是它自己 `def` 出来的那些。

## 注册表

注册表是 `emo` 模块——语言自己的函数组，像 `R` 和 `Exception` 一样内置于每个程序、无需 `require`。它的表面就是语言协议的完整清单：

| 条目 | 分派到 | 契约 |
| --- | --- | --- |
| `emo.to_string(x)` | `x.to_string()` | `def to_string() String` |
| `emo.length(x)` | `x.length()` | `def length() Int64` |

没有注册表条目的方法名就是普通方法——语言不在它上面分派。

这个关键字一职两用：`emo Name { ... }` 声明函数组，表达式位置的 `emo.` 访问语言自己的那个。任何包不得以短名 `emo` 绑定。

## 分派

**调用。** `emo.f(x, rest...)` 即 `x.f(rest...)`：receiver 恒为第一个参数，其余实参按原顺序透传——命名实参与尾随块同样透传，`emo.f(x, indent: 2)` 即 `x.f(indent: 2)`。

**构造。** 渲染路径是同一条规则，凡值变成文字处共用：

- `println(value)` 写出 `emo.to_string(value)` 加一个换行。
- 插值用 `emo.to_string` 渲染每个 `${...}` 部分。
- 容器用同一条目渲染其元素——`[Point.new(1, 2)]` 打印 `[(1, 2)]`。
- 未定义 `to_string` 的类渲染为它的结构转储——`#Point(x: 1, y: 2)`，其内字符串带引号，各目标逐字节一致。这是已定义的默认，不是静默回退：每个值都回答 `to_string()`。（根本无法渲染实例的目标会响亮拒绝，这是 freestanding 目标的一贯形状。）

不进入渲染的东西:`printf("%s", ...)` 只收 `String`——用 `emo.to_string(x)` 显式转换;`+` 从不拼接非 `String`——拼接是插值的事。

**契约。** 协议名出现在类体或接口体内时携带它的精确契约:`def to_string` 必须是 `() String`,`def length` 必须是 `() Int64`。其他任何签名都是一条写明契约的编译错误——`init` 已经遵循的同一条规则。协议名在别处是普通标识符:顶层函数、组成员、绑定、参数、字段叫 `to_string` 都没问题。协议方法是定义出来的，不是声明出来的——没有 conformance 子句；满足是结构式的，与接口完全一致。

```emo
class Point {
  def init(x Int64, y Int64) {
    self.x = x
    self.y = y
  }

  def to_string() String {
    return "(${self.x}, ${self.y})"
  }
}

println(Point.new(1, 2))           // (1, 2)
println([Point.new(1, 2)])         // [(1, 2)]
println("at ${Point.new(1, 2)}")   // at (1, 2)
```

对没有该方法的类型调用 `emo.f(x, ...)`，在类型可知处是编译错误，否则是运行时错误；缺方法错误在存在近似定义（`to_str`）时会把它指出来。`println` 从不因缺 `to_string` 报错——默认渲染就是它的答案。

## 什么不是协议

`==` 不是协议、没有条目：相等是语言规则规定的结构相等，对每个类型成立，无可覆写。注册表只分派方法、从不分派运算符——`a + b`、`a < b`、`a == b` 从不调用用户代码；领域类型拼写命名方法（`v.plus(w)`）。

没有缺方法钩子：调用不存在的方法是错误，永远不是回调。`to_string` 之外没有第二个渲染条目——一个钩子、一个已定义的默认。没有真值转换——条件就是 `Bool`。没有自定义 `case` 匹配器。

## 条目如何挣得位置

两个问题，都必须答是：

1. **该方法在语言表面上承重吗？** 或者有构造在它上面分派——`to_string` 由 `println`、插值、容器渲染分派——或者内建类型自己以规范共享名的身份携带它——`length`，`Array`、`String`、`Map`、`List`、`Bytes`、`ArrayBuilder` 全部实现为 `def length() Int64`。
2. **契约封闭吗？** 签名必须能精确陈述，使 checker 能在定义点和调用点校验。参数之间相互关联的操作做不成条目：集合变换（`emo.map(x, fn)`）必须把 `fn` 与 `x` 的元素关联起来，类型系统陈述不了——何况它的每次使用本来就是显式调用，而 `x.map(fn)` 已是直接形式。集合操作如果将来出现，是集合类型自己的方法。

注册表靠设计决策增长，而且长得慢。针对形状做泛型编程是接口的事——注册表是语言自己的保留集，它的价值就在于它的稀缺。
