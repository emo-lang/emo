# Networking

Networking is a first-class citizen: nearly every modern program talks over the network. Emo provides a unified asynchronous networking API. On the `ocaml` backend it runs on the same effects-based scheduler as the concurrency runtime — non-blocking sockets parked and woken by the scheduler, with TLS provided by OpenSSL bindings; on the TypeScript target it runs on Node's event loop, the emitted `await`s settling each call. The `net` and `http` packages declare `targets = ["ocaml", "c", "typescript"]`, and dependency resolution refuses them on every other target; the `c` target implements TCP and TLS.

The API is **direct style**: network calls look like ordinary blocking calls, and the scheduler switches processes under the hood. There is no `async`/`await` and therefore no function coloring — any function can perform IO, and the API ecosystem stays single-tracked. Timeouts are seconds, and every failure — refused connection, unresolvable name, exceeded deadline, closed socket — returns `(R.error, reason)`, the reason stating the peer, the operation, and the reason.

The socket surface is the standard library's `net` package; HTTP lives in the `http` package:

- **Sockets.** `net.connect(host, port, timeout)`, `net.connect_unix(path, timeout)`, `net.tls_connect(host, port, timeout)`, and `net.tls_connect_insecure(host, port, timeout)` — certificate verification is on by default, and the insecure variant is the explicit, visibly dangerous opt-out — return a `TcpConn`. `net.tls_connect_with(host, port, timeout, options)` takes a per-connection policy from `net.tls_client_options()`: a private trust store, a client certificate for mutual TLS, or a verification-name override. `net.listen(host, port)`, `net.listen_unix(path)`, `net.listen_tls(host, port, cert_path, key_path)`, and `net.listen_tls_with(host, port, cert_path, key_path, options)` return a `TcpListener`; `net.udp_bind(host, port)` returns a `UdpSocket`; `net.resolve(host)` resolves a name to its addresses. The full API reference lives in [docs/stdlib/net.md](../stdlib/net.md).
- **Connections.** `read_line()`, `read_exactly(n)`, `read_all()`, `write(data)`, and `close()` — a graceful close delivers pending writes first. `set_timeout(seconds)` bounds the operations that follow (the default is no timeout; `0.0` waits indefinitely). A listener serves `accept()` and reports `port()`; a datagram socket `send_to(host, port, data)`s and `recv_from()`s, and reports `port()`.
- **HTTP client.** `http.get(url)`, `http.post(url, body)`, `http.put(url, body)`, `http.delete(url)`, and the general `http.request(method, url, headers, body, timeout)` return an `HttpResponse` carrying `status`, `headers`, and `body`. `http.request_with(..., tls_options)` adds the per-connection TLS policy for `https` URLs. Redirects are never followed: a 3xx is a response like any other, and following it is the caller's explicit move. The full API reference lives in [docs/stdlib/http.md](../stdlib/http.md).
- **HTTP server.** The `httpd` package runs one process per connection: `httpd.serve(listener) -> (req httpd.Request) { ... }` answers a `Server` handle (`stop()` graceful, `wait()` joining the drain), the handler returns an `httpd.Response` value, and `httpd.router()` adds pattern routing (`{name}` wildcards, subtrees, 405 with `Allow`, cleanup redirects) through `httpd.serve_routes`. A listener from `net.listen_tls`/`listen_tls_with` serves the same handler over HTTPS. The full API reference lives in [docs/stdlib/httpd.md](../stdlib/httpd.md).

Layering is conventional: sockets (TCP/UDP/Unix domain, plus TLS) live in the `net` package, and HTTP rides it — the client in the `http` package, the server in the `httpd` package. TLS is an OpenSSL binding on `ocaml`, the system OpenSSL/LibreSSL on `c`, and Node's `tls` on `typescript`.
