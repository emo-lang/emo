# Step 55 — The standard library: `crypto`

**Milestone:** M21 — The crypto package · **Prereq:** none (`base64`
is the byte-discipline and all-five-golden working example; `math`
0.1.0 proves pure Emo carries real algorithms byte-identically on
every target) · **Related:** `stdlib/registry/base64`,
`docs/stdlib/base64.md`, `plan/step-51-tls-c-target.md` (the
system-library TLS route this package deliberately does not
duplicate) · **Status:** planned

## Why this step exists

A general-purpose language either ships crypto or ships a hole. The
reference survey is Go's `crypto` umbrella (pkg.go.dev/crypto@go1.27.3,
26 packages), and two observations from it shaped the scope:

- **Go keeps the broken past only to decrypt it** — DES, RC4, DSA,
  MD4 survive as deprecated packages for legacy data. A brand-new
  standard library has no such liability: it can decline them.
- **Half of Go's packages are protocol plumbing** — `tls`, `x509`,
  `asn1`, `pkix`. Emo already routes TLS through the system library
  (step 51: OpenSSL/LibreSSL behind the C runtime's conditional
  linkage), and that decision stands. What this step builds is the
  layer beneath every protocol: hashes, MACs, KDFs, AEAD ciphers,
  signatures, and the entropy source.

The pure-Emo rule is the point, not a compromise. `math` 0.1.0
established that fixed-order, fixed-coefficient source is
byte-identical across all five hosted targets; crypto's RFC and NIST
test vectors then pin every target to the same answer, and the
answers can be cross-checked bit for bit against Go's own
implementations, generated on this machine and frozen into the
goldens.

## Goal

`require "crypto"` gives the SHA-2 and SHA-3 hash families with
SHAKE, HMAC over any of them, HKDF and PBKDF2, the constant-time
compares, ChaCha20-Poly1305, AES with GCM and the block modes, and
Ed25519/X25519. MD5 and SHA-1 live behind `crypto.legacy` — the name
is the warning — present because the world's existing data needs
verifying, refused for every security purpose. `require "rand"` gives
the OS entropy source as its own native-backed package, so `crypto`
stays pure and five-target.

## Decisions settled here

- **One package, submodules by family.** `crypto` is a single
  versioned package — HMAC, the hashes, and the KDFs interlock, so
  one version axis avoids a dependency matrix. The public surface
  splits into sibling modules (`crypto.sha2`, `crypto.sha3`,
  `crypto.legacy`, `crypto.hash`, `crypto.kdf`, `crypto.cipher`,
  `crypto.sign`, after the `plot.mark` precedent); the machinery
  lives in `internal/` (compiler-enforced subtree privacy), after the
  `math` precedent.
- **`rand` is its own package.** Entropy is the one thing pure Emo
  cannot conjure; binding it per target would split `crypto`'s target
  list. `rand` declares the targets it can honestly serve; `crypto`
  declares all five and stays byte-identical everywhere.
- **The error split follows the house rule.** Wrong key length,
  wrong nonce length, a zero iteration count — contract violations,
  they raise. An AEAD tag that does not verify — a data reason — is
  `(R.error, "crypto: authentication failed")`. Reason strings begin
  `crypto:`.
- **String at the surface, Bytes inside.** Bytes ride as `String` in
  this standard library (`os.read`, `bufio`, `base64`), so keys,
  digests, and ciphertexts are `String` too and compose with
  `file.read`; the implementations work over `Bytes`.
- **AES lands as T-tables first.** The cache-timing caveat is
  documented in the same breath — a table lookup indexed by secret
  data is not constant-time. The AES-NI C shim for `c` is later
  optional hardening; GCM's GHASH is pure bitwise and carries no such
  caveat.
- **Constant-time is a source-level discipline, honestly labeled.**
  No secret-dependent branches or table indices in the source; what
  each backend's emitted code guarantees is documented per target,
  and the strongest claims are made only where they hold (`c`).
- **RSA waits.** It needs arbitrary-precision arithmetic, which is a
  foundation of its own; Ed25519 covers signing with fixed-limb field
  arithmetic. RSA/ECDSA return behind an internal bignum module when
  interop demands.
- **The vectors are the acceptance.** RFC and NIST suites from the
  specifications, companions generated by Go's own packages on this
  machine and frozen into `expected.txt` (the interop claim is then a
  diff), and Project Wycheproof cases sampled at the boundaries —
  truncated tags, tampered ciphertexts, block-edge lengths.

## Tasks

- [x] **T55.1** — The word discipline and the package skeleton: the
      probe first — `>>` measured arithmetic (sign-extending) and
      `<<` wrapping modulo 2^64 on the interpreter, byte-identical on
      `c`; `internal/word.emo` with the mask-idiom logical right
      shift (`(x >> n) & ((1 << (64 - n)) - 1)` for constant
      `n > 0`), `rotl`/`rotr` in both widths, and the big-endian
      u32/u64 `Bytes` load/store; `stdlib/registry/crypto/0.1.0`
      (manifest over all five targets) with the root `crypto.emo`
      carrying `subtle`; the vectors verified against an independent
      computation, pinned from T55.2 on through the digest goldens —
      an example cannot reach `internal/`. The probe also flushed a
      c-target corner: a module bound to a name (`const word = word`)
      answers dynamic at its use sites, and the dynamic world refuses
      the bitwise operators — the package's modules call their
      internals through the direct qualified path (`word.lshr(…)`),
      never through a wiring const.
- [x] **T55.2** — SHA-256 and SHA-224 (FIPS 180-4): streaming
      (write/sum/reset/size) and one-shot in `crypto.sha2` over
      `internal/sha256.emo`'s engine (the hasher's mutable state
      riding one `Bytes` box — fields are assigned only inside
      init); the golden `examples/crypto_hash` takes the RFC 6234
      suite plus Go `crypto/sha256` companions, with the streaming,
      sum, reset, and hex panels; `examples/crypto_hash_million`
      (c-only) rides the million-`a` vector; `crypto.hex_encode`/
      `hex_decode` joined the root.
- [x] **T55.3** — The SHA-512 family (512/384/512-224/512-256) over
      64-bit lanes in `internal/sha512.emo` (constants derived from
      the spec, the /224 and /256 initial words through the
      generation function), the `Wide` class beside `Digest` in
      `crypto.sha2`; SHA-1 and MD5 in `crypto.legacy`, one-shot only;
      the golden grows to 98 Go-agreed vectors; and the OCaml
      emitter's negative-Int64-literal bug flushed and fixed.
- [x] **T55.4** — The `Hash` interface in `crypto.hash` (`Digest`
      and `Wide` answer it by shape); HMAC over the SHA-2 family in
      `internal/hmac.emo`, one-shot, the engine riding sha2's
      one-shots through a variant code so no module cycle forms; the
      golden grows to 134 Go-agreed vectors with RFC 4231's cases
      (the 131-byte keys included).
- [x] **T55.5** — HKDF and PBKDF2 in `crypto.kdf` over
      `internal/kdf.emo` (extract documented as the HMAC call it
      is; the 255-hash-length cap and the iteration floor raise; the
      count a plain argument); the golden at 145 Go-agreed lines
      with RFC 5869's cases and RFC 7914's PBKDF2, and
      `examples/crypto_kdf` (c-only) pinning the 4096-iteration
      classic.
- [ ] **T55.6** — SHA-3 and SHAKE (FIPS 202): Keccak-f[1600] over
      64-bit lanes, the four fixed-output hashes, SHAKE128/256 with
      explicit output length; KATs plus Go companions.
- [ ] **T55.7** — The `rand` package: per-target OS entropy
      (getrandom / `/dev/urandom` on `ocaml` and `c`,
      `crypto.getRandomValues` on `typescript`,
      `crypto:strong_rand_bytes` on `beam`; the wasm leg measured and
      refused by the target list if the runtime cannot honestly serve
      it); tests ride a pure-Emo HMAC-DRBG (SP 800-90A) so the
      deterministic sequences are goldens.
- [ ] **T55.8** — ChaCha20-Poly1305 (RFC 8439): the quarter-round,
      the Poly1305 limbed accumulator, `seal`/`open` with the
      `(R.error, …)` authentication failure; RFC vectors, Go
      `chacha20poly1305` companions, Wycheproof boundary cases
      sampled.
- [ ] **T55.9** — AES and GCM: the block cipher as T-tables (the
      timing caveat documented), GHASH bitwise, CTR/CBC with PKCS#7
      for the interop shapes; NIST vectors plus Go AES-GCM
      companions, Wycheproof's GCM edge cases sampled.
- [ ] **T55.10** — Ed25519 and X25519 (RFC 8032, RFC 7748): field
      arithmetic over `Int64` limbs, the width decided by
      measurement (radix 2^26 five-limb is the fallback shape);
      RFC vectors plus Go `ed25519`/`ecdh` companions, including
      X25519's all-zero-output refusal.
- [ ] **T55.11** — The docs: `docs/stdlib/crypto.md` and

      new goldens into the golden lists as their targets land them;
      `plan/README.md`'s status table.
