# 计算器

`apps/` 下的第一个应用:一台四则计算器,用 Emo 写一次,跑在每一个 EmoUI 后端上——终端、服务端渲染的页面、AppKit 窗口、GTK 4 窗口、浏览器 DOM 和帧缓冲。EmoUI 的设计是一个应用一个应用地往前走的,每个应用都是 `projects/emo-ui/apps/` 下一个独立的项目;这是第一个,也是最小的、仍然会有人真去用的应用。

选计算器,是因为它需要的恰恰是每个后端都已经能递交的那一种事件——按钮上的一次点击——所以从应用到七个平台之间,输入这一侧没有任何东西挡路。真正挡了路的,记在下面的[计算器说不出的东西](#计算器说不出的东西)里。

```
 0
 [ C ]   [ < ]   [ +/- ]
 [ 7 ]  [ 8 ]  [ 9 ]  [ / ]
 [ 4 ]  [ 5 ]  [ 6 ]  [ * ]
 [ 1 ]  [ 2 ]  [ 3 ]  [ - ]
 [ 0 ]  [ . ]  [ + ]  [ = ]
```

## 目录

```
apps/calculator/
  package.emo  main.emo  number.emo  test.emo    应用本体,emo/ui_calculator
  expected.txt                                    轨迹:每一帧之后的显示
  check.sh                                        门禁
  debug/  ssr/  tui/  fb/                         会话被重放进来的入口
  macos/  gtk/  browser/                          由人来操作的入口,以及一个会话孪生
```

应用是 `emo/ui_calculator`,只钉住 `emo/ui`。`main.emo` 是人操作的那台计算器——一个 model、一个纯的 `update`、一个纯的 `view`;`number.emo` 是它底下的算术。两者都不点名任何平台。

其余每个目录都是一个平台的入口:自成一个包,以应用和该平台的后端为依赖,于是只有入口会点名平台。一个入口只有几行——一个 `require`、一个传入该平台单位的 `view`、一次 `ui.run`——两个窗口包和浏览器包则各持两个入口:`main.emo` 由人来操作,`session.emo` 为门禁打印每一帧的显示。两者共用的东西——窗口和单位——在 `mount.emo` 里。

## 应用

**键。** 十九个消息,次序就是键面上的次序:`clear`、`back`、`sign`、十个数字、`dot`、`add`、`sub`、`mul`、`div`、`equals`。链式运算从左到右(`7 + 8 * 2 =` 是 30);一个运算符按下去时若已有运算符在等,以后按的为准(`5 + - 3 =` 是 2);`=` 重复得出该结果的那次运算(`2 + 2 = = =` 是 8),而在有运算符等着时把显示当作两侧(`5 + =` 是 10)。正负号键给正在输入的数取负,在运算符之后开始一个负的右操作数,对一个结果则把它翻转。退格缩短正在输入的数,对结果不动。一个输入最多取十五位数字——恰好是一个 double 能精确携带的位数。

**显示。** 十二位有效数字,四舍五入,去掉末尾的零:三分之一是 `0.333333333333`,`1.1 + 2.2` 是 `3.3`,那个数加一半是 `10000000000.5`。普通写法写不下时用十的幂——`1e+15`、`9.99e+15`、`3.33333333333e-6`——并且从不用上标:终端和帧缓冲画得准的只有 ASCII。一次失败会在显示上留下 `Error`,除 `C` 之外任何键都够不着它。

**值域。** 超出 `1e100` 的结果就是那次失败——十位袖珍计算器也是在这里溢出的——而这个界,正是让算术不越过每个 target 都能做到的范围的东西。对于离开有限范围的浮点数,Emo 的各 target 并不一致:`x / 0.0` 在解释器和 `ocaml` 上是运行期错误(E3005),在 `c`、`typescript` 和 `wasm` 上是无穷大,而溢出的浮点数在 `beam` 上会抛出。Emo 没有 catch,所以一次没有守卫的 `1 ÷ 0` 结束的是整个应用,而不是在显示上留下一个词。因此 `number.emo` 在可能抛出的算术之前先检查每个运算,回答 `(R.ok, value)` 或 `(R.error, why)`;`update` 把一个错误变成显示上的那个词。显示的数字是 `Int64` 算术,而不是 `printf`(`wasm` 和 `riscv64` 不携带它)或 `Float64.to_string()`(它只打印六位有效数字)。

**tag。** 一个键的 tag 就是它在键盘上的位置:`view` 在构造任何东西之前,按键盘的次序注册这十九个消息,`tag_of("7")` 就是这个次序给它的值。一个会话用键面上的东西来命名——`["7", "+", "8", "*", "2", "="]`——从来不用数字,无论在入口里还是在门禁的脚本里。

**单位。** `view(reg, m)` 为终端布局计算器。一个 `Style` 数字在终端上是一格,在 AppKit 窗口里是一点,在 web 上是一像素,所以 `view_at(reg, m, unit)` 从唯一知道平台的那个模块——入口——那里接过键与键之间的间距和四周的留白。键本身不带任何尺寸:每个键要的是它所在行的均分(`grow`),高度则是其标签的高度,因为 `Style` 里没有一个数字在终端上和在窗口里是同一个长度。

`test.emo` 是应用自己的测试,由解释器运行的八十条断言:显示的数字、输入的十进制数、带守卫的运算、每个键做什么,以及键盘的 tag 在树里是怎样携带的。

## 运行

**编译器。** 用来构建它的 `emo`,是从这份检出里编出来的那个:应用的各个包在源码树里,它们所用的语言也在源码树里。在一台还没有它的机器上——下面是 Debian 和 Ubuntu 的包名,Fedora 对应 `gcc make pkgconf-pkg-config openssl-devel gtk4-devel opam`:

```sh
sudo apt-get install -y build-essential pkg-config libssl-dev libgtk-4-dev git opam
opam init -a
opam switch create 5.5.2
opam install -y dune cmdliner eio_main ssl yojson digestif
eval $(opam env --switch 5.5.2)
cd <仓库目录>
dune build src/emo_cli/emo.exe
```

最后一行得到的就是编译器,在 `_build/default/src/emo_cli/emo.exe`;`just build` 以 release profile 编同一个文件,`just install` 把它链接到 PATH 上,成为 `emo`。`libgtk-4-dev` 是 GTK 4 的那一半——头文件、pkg-config 文件和库——GTK 入口需要的就只有它:`emo build` 经后端的清单找到 GTK 4。一键安装得来的发布版 `emo` 替代不了它:它可能还说不了这棵源码树的语言。

**注册表。** 应用的各个包要经由一份从被测源码暂存出来的注册表才能取到,和每个门禁暂存注册表的方式一样:

```sh
scripts/stage-registry.sh <registry-dir>
cd projects/emo-ui/apps/calculator
```

| 平台 | 入口 | 今天一个人能做什么 |
|---|---|---|
| macOS | `macos/main.emo` | 在 AppKit 窗口里点键 |
| GTK 4 | `gtk/main.emo` | 在 GTK 窗口里点键 |
| 浏览器 | `browser/main.emo` | 在 `index.html` 的页面里点键 |
| 终端 | `tui/main.emo` | 看窗口会话重放——还没有按键源 |
| 服务端渲染 | `ssr/main.emo` | 读页面和它的片段——还没有请求循环 |
| 帧缓冲 | `fb/main.emo` | 看窗口会话画在一张托管画布上 |

下面每个代码块都从应用的目录出发,而入口要从它自己的目录构建:`emo build` 读的是当前所在的那个包,入口属于别的包时它回答 E5011,并点名该在哪个目录里运行。两个窗口入口为 `c` 构建:

```sh
cd macos                                  # 或 gtk
EMO_REGISTRY=<registry-dir> emo build main.emo --target c -o calculator
./calculator
```

页面为 `browser` 构建:

```sh
cd browser
EMO_REGISTRY=<registry-dir> emo build main.emo --target browser -o out.js
```

页面是 `browser/index.html`,旁边放着 `out.js`;树挂进它的 `#emo-root`。应用什么也不打印——`./check.sh` 会把三个构建产物留在 `.emo-build/check/` 下,可以直接运行。

**没有显示器时**——或者想看它工作,而不是看它的样子——窗口的会话入口会自己点自己。像应用一样构建,带上 `EMO_GUI_AUTOTEST=1` 运行,它重放窗口会话然后退出;在 `xvfb-run -a` 下它不需要桌面:

```sh
cd gtk
EMO_REGISTRY=<registry-dir> emo build session.emo --target c -o session
EMO_GUI_AUTOTEST=1 xvfb-run -a ./session
```

它每帧打印一行 `display <显示的内容>`——也就是 `expected.txt` 的开头几行——此外什么也没有。

## 会话与门禁

一个会话,159 个键,走到每一个键和显示会有的每一种状态。每帧打印一行的后端整个重放它,其余的重放它开头的若干键:

| 会话 | 键数 | 由谁重放 |
|---|---|---|
| 托管会话 | 159 | 无头入口和页面 |
| 窗口会话 | 前 54 个 | 终端、帧缓冲和两个窗口 |
| 页面会话 | 前 6 个 | 服务端渲染入口,以及 `beam` 上的帧缓冲 |

窗口会话的长度就是一个原生 shim 能接受的长度——最多六十四个 tag,每拍点一下;页面会话的长度则是一份文档值得打印多少帧。每个入口每帧把显示打印一次,写作 `display <显示的内容>`,所以较短会话的字节就是托管会话开头的那些行,而 `expected.txt`——无头入口在解释器上的输出——是每个入口都钉住的同一份文件。

```sh
./check.sh
```

门禁暂存它自己的注册表,然后:

- 应用通过类型检查,它的八十条断言通过,并为 `riscv64`(金属的 target)降低;
- 无头入口和服务端渲染入口在五个托管 target 上逐字节一致,终端入口在四个能写 stdout 的 target 上一致(它对 `wasm` 的拒绝按名字钉住),帧缓冲入口在四个上一致——在 `beam` 上跑的是页面会话,因为一帧像素在那里要花好几秒([见下](#关于各个-target));
- 终端、帧缓冲和服务端渲染的金测在各自的帧之外带着轨迹,它们带的那部分必须是 `expected.txt` 的开头;
- 页面由浏览器后端的桩页面逐键点完整个托管会话,打印出 `expected.txt`;
- 每个窗口在 `EMO_GUI_AUTOTEST` 下重放窗口会话,打印它的那些行,并报告一共制造了二十个控件——显示和十九个键——在五十四次按键里一个没有多造,这正是从一个真实工具包那里看到的保留式 diff。

`projects/emo-ui/check.sh` 和各后端的门禁一起运行它,项目因此只有一个入口。

## 计算器说不出的东西

这正是这个应用的用处。每一条都是计算器需要、EmoUI 今天没有对应的词、应用绕了过去的东西;每一条都是留给核心的设计问题,而不是在这里做的改动。

1. **`Style` 的数字没有单位。** 同一个间距,在终端上是一格,在窗口里是八点,在 web 上是六像素。`view_at` 的 `unit` 是绕过去的办法——由入口来选——它说出了核心缺的东西:一个由各后端各自解析的长度,就像平台自己的工具包都有一种那样。
2. **一个节点没法要「均分」。** `grow` 分的是每个子节点自身宽度之外剩下的部分,所以只有在标签按字符量的地方键才是等宽的——终端、帧缓冲和两个原生盒模型。在真实浏览器里,标签有它字体的宽度:`/` 是 40 px,而数字是 46 px。固定宽度不是答案,因为在终端上那就是四十格。
3. **叶子节点没有自己的高度。** 一个键在终端和帧缓冲上只有一行高,在别处是一个默认按钮;`Style` 里的 `height` 会是同样多的格数和像素。
4. **`Style` 只说布局,别的都不说。** 没有颜色、没有字号、没有文字对齐、没有面板,于是显示和键的标签一样大、靠左对齐,运算符长得和数字一样,也没有主题。在 web 上,是 `index.html` 自己的样式表为树撑起那张卡片——页面是后端的约定,也是唯一还能说这件事的地方。
5. **标签是字节。** 终端后端用 `length()` 量按钮的标签,帧缓冲一次一个字节地走它,所以 `×`、`÷`、`±` 和 `⌫` 会在一个上面错位,在另一个上面画出缺字的方框。键面是 ASCII——`*`、`/`、`+/-`、`<`——显示里的十的幂写作 `e+15`。
6. **没有键盘。** 一个窗口只接点击,别的都不接;终端入口重放脚本,是因为后端没有按键源;服务端渲染入口只打印,是因为没有请求循环。`term` 包能在 `c` 上读键,但哪个键表示 `C` 是应用说了算的事,而核心的事件只带一个 tag,别的都不带——这是
   [`docs/emo-ui-missing.md`](../../../../docs/zh-CN/emo-ui-missing.md)
   里的第一个问题。
7. **被保住的控件也保住了它的焦点。** 窗口打开时 AppKit 会画出第一个键的焦点环,这是保留式 diff 在一个没人 Tab 到的按钮上尽它的本分。

## 关于各个 target

计算器遇到并且打了交道的一些 Emo 事实;`CHECK.md` 带着探针。

- 一个被零除的浮点数和一个溢出的浮点数,在各 target 上并不是同一个值——值域和带守卫的运算是上面的回答。
- `riscv64` 不降低 `String.chars()`,所以输入的数按字节走;`test.emo` 守着同一个集合,整个包才能为金属降低。
- 在 `beam` 上,存一个像素会拷贝画布的整块 `Bytes`:同样 46,080 次写入,写进 368 KB 的画布要 2.0 秒,写进十倍大的画布要 18.7 秒。计算器的一帧在 384x240 的画布上在那里要 8.2 秒,而它的布局只要 0.03 秒,所以帧缓冲入口画的是一张 256x148——计算器量出来的尺寸——它的 `beam` 腿是页面会话的七帧。

## 还没做的

- **金属和 Wayland。** 应用能为 `riscv64` 降低,但没有任何 EmoOS pass 在一个属于它自己的窗口里运行它,Wayland 客户端里也没有它的瓦片。桌面的应用窗口高 128 像素;计算器在这个字号下量出来是 148,它的五行键是 116。
- **键盘,以及服务器。** 接上 `term` 的终端入口、能接收键入数字的窗口、请求循环背后的服务端渲染入口——每一项都是核心或某个后端里独立的一件工作。
- **更大的计算器才有的键**——百分号、存储、历史——以及 `apps/` 下的第二个应用。
