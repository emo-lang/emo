# The kernel's high-half layout

How the kernel lives under Sv39: the two halves of the address space,
the table the kernel builds for itself, the two aliases every byte has,
the boot that gets from OpenSBI's physical entry to a kernel
running paged, the per-process tables every user pass runs on, and —
since T6.3 — the trampoline every trap crosses. Fixed as of T6.1
(2026-10-29), T6.2 (2026-10-29), and T6.3 (2026-10-30); the
page-fault kill (T6.4) and the isolation goldens (T6.5) extend this
document rather than replace it.

Chinese translation: [`sv39.zh-CN.md`](sv39.zh-CN.md).

## The two halves

Sv39 translates 39-bit virtual addresses — 512 GiB — and requires the
upper 25 bits of a 64-bit address to copy bit 38, so the space is two
halves with a hole between them: the lower half, `0` to
`0x3fffffffff`, and the upper half, `0xffffffc000000000` to the top.
The lower half is the user's; the upper half is the kernel's.

Every kernel address is its physical address plus `koff`, the base of
the upper half — `0xffffffc000000000`, which as an `Int64` is −2³⁸ —
so the kernel image, the free RAM, the fixed pages, and the devices
all sit at one fixed offset from where they physically are, and a
pointer's sign says whose it is: a kernel address is negative, a user
address positive. The kernel image links at the high alias of the
load address OpenSBI enters (`0xffffffc080200000`); `link.ld` keeps
every section's load address physical, so QEMU and the firmware see
the image where they always did.

Why the high half rather than the identity map the window ran on: the
user gets the whole lower half — one fixed load address for every
user ELF, no kernel range to avoid (T6.2); the kernel's mappings can
be shared into any address space without colliding with a user's; and
the sign bit is a test no comparison against a table can beat.

## The kernel's table

Built once at boot by `sv39.emo`, over frames the allocator hands out,
and never changed afterwards. What it maps, as QEMU's monitor reads it
back (`info mem`):

| Virtual | Physical | Size | Bits | Contents |
| --- | --- | --- | --- | --- |
| `0xffffffc080200000` | `0x80200000` | text | `r-x` | the kernel's code |
| text end | | rodata | `r--` | the read-only data, the embedded user image included |
| rodata end – `0xffffffc088000000` | | to the RAM's top | `rw-` | data, bss (the 96 MiB heap, the slots, the green stacks), the frame region, the fixed pages |
| `0xffffffc010000000` | `0x10000000` | 4 KiB | `rw-` | the 16550A |
| `0xffffffc00c000000` | `0x0c000000` | 4 MiB | `rw-` | the PLIC |
| `0x80200000` | `0x80200000` | to the RAM's top | `rw-` | the supervisor's window onto the low RAM — megapages, **no U** (T6.2) |

The rules the table follows:

- **Permissions by linker boundary.** `link.ld` aligns the ends of
  `.text` and `.rodata` to a page and exports them; the stub passes
  both to the builder, which records them on the Sv39 page — every
  later table (each process's, T6.2) draws the same picture — and text
  is RX, rodata R, and everything from the data onward RW.
- **Granularity by alignment.** A range maps in 2 MiB megapages
  wherever both addresses sit on a megapage boundary with a megapage
  to go, 4 KiB pages elsewhere — so the image's first two megabytes,
  where the permission boundaries fall, cost one small table, and the
  hundred megabytes behind them cost sixty-two entries. The whole
  kernel table is five frames: the root, the level-1 table for the
  RAM, the level-0 table for the image's head, the level-1 table for
  the MMIO, the level-0 table for the UART's page — one block split.
- **Every leaf is accessed and dirty.** The kernel keeps no use
  counts, and an implementation that traps on a clear bit must not
  get the chance. No global bit, ASID 0.
- **Not one entry carries U.** The window's two U gigapages of T6.1
  are gone (T6.2): the kernel's table maps the kernel's half and the
  supervisor's low window, and nothing runs in U-mode on it — the
  boot pass adopts its own table at the enter shim, and every user
  process runs on one of its own.
- **The supervisor's low window is the one low mapping.** The loader's
  copies into the window, the user stub's cells (`0x87fff000`), the
  process service's read of the parked program cell, and the gate's
  answers into a parked pass's trap frame are all low addresses, and
  a kernel process runs on this table: the window is how the kernel's
  own bookkeeping reaches them. It is RW, no U, never executed, and
  it begins at the load address — the firmware's PMP-locked region
  stays in no mapping, as T6.1 decided.
- **The firmware is in no mapping.** `0x80000000`–`0x80200000` is
  OpenSBI's; the kernel never touches it, and the SBI calls the kernel
  still makes (the poweroff) are M-mode ecalls, which run untranslated.

## The entry format and the walk

A table is one 4 KiB frame of 512 eight-byte entries. An entry is
`PPN << 10 | flags`: the physical page number of the next table or of
the page, and the bits V (valid), R, W, X, U (the user may reach it),
G, A (accessed), D (dirty). An entry with any of R, W, X set is a
leaf, at whichever level it sits — a 4 KiB page at level 0, a 2 MiB
megapage at level 1, a 1 GiB gigapage at level 2; an entry with none
is a pointer to the next table. The walk takes nine bits of the
virtual address per level, bits 38–30 for the root, 29–21 for the
middle, 20–12 for the last, three levels down from the root in
`satp`.

`sv39.emo` is the untyped-memory discipline the README decides —
`Int64` addresses, `peek`/`poke`, bit masks, no value of the language
pointing into a table — and every def is a fully typed native body.
Its rules are strict: a leaf met on the way down is a kernel bug (a
larger page already covers the address), an address mapped twice is a
kernel bug, a leaf or a range off its page boundary is a kernel bug —
each the loud end (`sv39: …` on the console, then the SBI poweroff),
never a silent overwrite. `lookup` is the software walk, what the
hardware does on a TLB miss, and the builder walks its own table for
the addresses the next instructions depend on before it answers the
root — a wrong table dies with a line, not with a fault at the `satp`
write.

## The two aliases, and who uses which

Every byte of the machine has two addresses: the kernel's, in the high
half, and the physical one.

- **The kernel's address is the currency.** Everything the kernel's
  own loads, stores, and fetches reach — the image, the allocator's
  blocks and frames (`frames.emo`'s region bounds, links, and answers
  are all kernel addresses), the rings and the fixed pages, the
  devices — is named by its kernel address, in the Emo (`koff` plus
  the physical constant) and in the shim's assembly (`EMO_KOFF` plus
  the physical constant).
- **The physical address appears in exactly three places**: in a leaf
  entry (`sv39.emo` writes `pa_of(kernel address)`), in `satp` (the
  shim takes the root's physical address), and as the user's address
  of its own memory — the user image runs at `0x87100000` as before,
  a user pass's stack and arena blocks are reached by the pass at
  their physical addresses (each pass's table maps them at identity),
  and the user's cells at `0x87fff000` are the user's. T6.2 did not
  move the user's world; it closed what else the user could reach.
- **The kernel reaches user memory by the user's addresses, with
  SUM.** The gate's buffer reads, the loader's copies into the window,
  the trap frames the shim lays on a user stack, the synthetic frame a
  spawn builds — all S-mode accesses to pages carrying the U bit,
  which `sstatus.SUM` permits. The stub sets SUM once the kernel's
  table is live, and the resume stub sets it again on every return
  into any mode: SUM is the kernel's property, not the frame's — a
  spawn's synthetic frame carries a bare `sstatus`, and a return that
  trusted it would drop SUM and fault at the next trap's first store.
- **Two translation points, both explicit.** The arena handoff at the
  user's cells (`trap.S`): the slot's cursor and end words are kernel
  addresses, the cells take the user's, so the offset comes off on the
  way into U-mode and goes back on at the trap out. And the reaper's
  stack give (`frames.give`): the runtime names a dead pass's stack by
  the address the pass ran on — physical — and the allocator
  translates a physical base to the kernel's before judging it with
  the same strict checks as any other. The addresses the pass runs on
  are the ones its own table maps; nothing ends here — the identity of
  the user's world survived T6.2 on purpose.

## The per-process tables (T6.2)

Every user process — the boot pass and every spawned pass — runs on
its own Sv39 table, built in Emo (`space.emo`) from frames the
allocator hands out. What a pass's table maps:

| Range | Bits | Contents |
| --- | --- | --- |
| the kernel's half (`map_kernel`, no low window) | `r-x` / `r--` / `rw-`, **no U** | the kernel's image, the fixed pages, the devices — everything a trap into the kernel needs |
| the image's segments, by page-union permission | `r-x` / `rw-` / `rwx` where the ELF's segments share a page, **with U** | the pass's code and data |
| the pass's stack block, identity | `rw-u` | its own 64 KiB |
| the pass's arena block, identity | `rw-u` | its own 64 KiB |
| `0x87fff000`, identity | `rw-u` | the user cells page — the stub writes it, the trap shim hands the arena through it |

The rules:

- **U-mode's world is exactly those pages.** Code RX, data RW, its
  own stack and arena, the cells page — and the kernel's whole high
  half mapped without U, because the kernel runs on whichever table
  `satp` names and a trap out of a pass must find its own world.
  Every other byte of the machine is either absent from the table (a
  wild access page-faults) or present without U (U-mode cannot
  touch it). The weak-isolation window is closed.
- **The kernel half carries no low window in a user table.** The
  supervisor's window is megapages and the user's pages are 4 KiB
  ones in the same half of the same tree — a table carrying both
  meets a leaf blocking the walk. A table the kernel runs on inside
  a trap needs nothing the pass's own mappings lack: everything the
  shim touches is either high or the caller's own mapped pages.
- **The passes of one image share its pages.** A spawned pass
  re-enters the top level and finds the tokens the parent poked —
  the spawn semantics since T4.4, unchanged. The per-process part is
  the table: its own stack, its own arena, and a kernel half it
  cannot reach.
- **Built at spawn, strictness inherited.** `space.build` runs inside
  `emo_user_spawn`'s masked region (the runtime's build hook, zero in
  every image without per-process spaces): `frame_take`, clear, the
  kernel half (`sv39.map_kernel`), the segments from the loader's
  parked table with their ELF permissions translated plus U — the
  boundary page where text and data share a 4 KiB page gets the
  union, a page two segments claim at different physical addresses
  is the loud end — then the cells page, the stack block, the arena
  block, and the root's physical address into the slot's space word
  (872; the slot stride is 880).

**The switch is the pick's.** `emo_sched_pick` — the one place every
cooperative and preempted switch flows through — carries the incoming
slot's space word through the runtime's resolve hook and, on a root,
the write hook (`emo_os_satp_switch`: fence, write, fence). The word 0
means the kernel's own table, every green process's answer; the
resolve keeps a cache (the Sv39 page's third word) of what `satp`
names now and answers −1 when the incoming word resolves to it, so
the kernel's processes switching among themselves fence nothing. The
switch happens before a register of the incoming process is loaded —
the outgoing context's volatile registers are dead at a switch — and
inside the scheduler's masked region, so no interrupt can land
between the resolve and the `sret` that rides the new table. The
slot pointer rides s1 across the hook calls (a1 is the caller's to
lose, and the resolve is ordinary typed Emo whose own calls spend it
freely). The trampoline (T6.3) refines the transition; nothing here
depends on which half of it a trap crosses.

**The boot pass's table is built at stage time.** The loader
(`user.emo`) builds it after parking the segment table and before
parking the entry — a build that fails leaves the entry zero and the
machine never enters U-mode — and parks its physical root in the
handoff page's space cell (`0x870021c8`). The enter shim
(`emo_os_user_boot`) takes it into the root slot's space word (the
runtime's `emo_space_set`), adopts it into the switch's cache
(`space.adopt`), and performs the satp switch before the `sret` — so
the boot pass's word is in its slot before its first trap can
preempt it, and the first switch back to it installs the same table.

## The trampoline (T6.3)

A trap out of U-mode used to obey the pass twice over: the frame went
wherever the pass's `sp` pointed, and the kernel's dispatch ran on the
pass's table. The trampoline removes both. It lives on its own page —
`link.ld` gives the `.emo_tramp` section a page-aligned page at the end
of the text, alone on it — and `map_kernel`'s text RX carries that page
into every table, no U: the same virtual address in every space,
mapped for the supervisor's fetch and unreachable from U-mode.
`stvec` lands there for every trap, kernel and user alike.

**The path is chosen by a swap.** `sscratch` holds the running pass's
*trap anchor* while user code runs — the identity address of its fixed
trap frame — and the sentinel 0 while kernel code runs. The entry is
two instructions before anything else: `csrrw sp, sscratch, sp`, then
a branch on sp. A user trap finds the anchor in sp (nonzero) and the
interrupted user sp parked in `sscratch`; a kernel trap finds 0,
undoes the swap with the second `csrrw`, and jumps to the shim, which
proceeds byte-for-byte as it always has, framing on the interrupted
kernel stack. No register is spent before the interrupted state is
safe: the user path saves all 32 sp-relative into the anchor frame
first, recovers the interrupted sp from `sscratch` into the word below
the frame (the sp slot), zeroes the sentinel, and only then spends a
register.

**The anchor is memory no execution uses for live data.** A spawned
pass anchors at the bottom of its own stack block: the 544-byte frame
at block+552, the sp slot in the word below — beneath any call chain
the block's top can grow, because a descent that deep is the overflow
the block's edge used to swallow anyway. The boot pass anchors in its
own trap page, `0x87ffe000`, the fixed page under the cells page,
mapped rw without U into every table by `space.base`: the image's
stack is the stub's own and the heap is live data, so the page is the
scratch that is the boot pass's alone. The frame region is scratch
while the pass runs and the frame while it is stopped — a pass cannot
run and be stopped at once, so nothing user-side can reach a parked
frame, and the next trap rewrites every word of it before any is read.
A wild sp is saved and handed back, never obeyed.

**The transition's middle swaps `satp`, through the pick's own pair.**
The trampoline resolves word 0 (`emo_space_hook`) and calls the write
hook (`emo_os_satp_switch`) on the answer — the same resolve/write
discipline the pick uses, so the Sv39 page's cache stays true about
what `satp` holds; a raw `csrw` here would leave the cache saying the
kernel's table when a user's is live, and the pick's next resolve
would skip a needed write. After the swap the dispatch runs on the
kernel's table **and the kernel's trap stack** — 8 KiB of `.bss` the
trampoline puts into `sp` — so no kernel line descends through the
pass's frame into the pass's memory. The frame itself is reached
through `emo_os_trap_frame`, the base both prologues park (the anchor
for the trampoline's, the interrupted kernel sp minus 544 for the
shim's) — never through sp, whose value now differs by path, and the
slot below the frame is the one word below it anyone touches.

**The sret home is the resume's.** The answer and home paths resume
directly, without a pick — and the trampoline left the kernel's table
live, so the resume's user path brings the pass's own table back
through the same resolve/write pair before the `sret` (the parked and
preempted contexts get this for free from the pick). It re-arms the
anchor (`emo_os_anchor_arm`), restores every register while sp is
still the frame's top, and moves sp **last**, by its own self-relative
load from the slot below the frame — the interrupted sp the pass chose
is returned verbatim, whatever it was. The kernel path zeroes the
sentinel and keeps its sp: a kernel frame is on the interrupted kernel
stack already. The synthetic frame a spawn builds sits at the anchor
(the block's bottom), parking the initial sp in the slot — the pass
enters U-mode at the top of its stack, and its first trap lands on its
own frame.

## Boot

1. OpenSBI enters at `0x80200000`, physical, `satp` off. The stub runs
   at the physical alias — `la` is PC-relative, so every symbol
   answers its physical address — clears `.bss`, and writes the boot
   table into one zeroed page: `root[2]`, RAM at identity (`rwx`), so
   the instructions after the `satp` write keep fetching; `root[258]`,
   RAM at the high alias; `root[256]`, the first gigabyte of MMIO at
   the high alias. Then `satp` (mode 8, the root's PPN), `sfence.vma`,
   and a jump to the high alias of the next instruction.
2. From there everything is the high half, on the boot table: the
   stack by its kernel address, the hooks (console, blocks, resume),
   the trap init, the runtime init, the frame allocator's boot.
3. `sv39.boot` builds the kernel's table — `frame_take` splits a block
   into sixteen frames, the ranges above map, the builder walks its
   own table for the image, the data, the root, its page, the UART,
   the window — and answers the root's physical address. The shim
   `emo_os_satp_switch` fences, writes `satp`, fences, and answers the
   value written; the stub keeps it on the Sv39 page beside the root
   the builder recorded, and sets SUM.
4. The program's second line is its own check: `sv39_report` reads the
   live `satp` back, requires mode 8 and the root the builder
   recorded, and prints `sv39 8 0x<root>` — or ends the machine with
   `sv39: the live table is not the kernel's`. `run.sh` pins the line
   first in its chain.
5. After the program returns, the loader stages the user image and
   builds the boot pass's table (T6.2); the enter shim switches `satp`
   to it before the first `sret` into U-mode. From there every switch
   swaps tables with the process.

Why a boot table at all: the Emo that builds the real table is itself
linked high and reads the allocator's page through a kernel address —
not one instruction of it could run untranslated — so three stores in
the stub make the high half exist before the first Emo instruction,
and the Emo-built table then replaces the gigapage sketch with the
permissions the kernel means.

## The shims

`sv39.S` holds the two privileged instructions no Emo spelling
reaches: `emo_os_satp_switch` (a root's physical address in `a0`;
`sfence.vma`, the `satp` write, `sfence.vma`; the written value
answered) and `emo_os_sfence` (the whole TLB). The division of labor
is the gate's: Emo builds and reads the tables, the shim writes the
CSR. Since T6.2 the write hook is the pick's switch (the runtime's
`emo_space_write_hook`, parked by the kernel's stub beside the resolve
hook), and the enter shim's boot-pass switch the other caller; the
trampoline (T6.3) is the next.

## Page faults (T6.4)

A page fault is a kill, not a question. The three causes — instruction
fetch (12), load (13), store (15) — arrive like any exception the gate
does not own, and the fault route (T4.6's split on SPP) ends the
offending pass: the report, the slot done, the frame abandoned, the
blocks home, the machine continuing. What T6.4 adds is the name: both
trap prologues — the shim's and the trampoline's — save `stval` beside
`scause` and `sepc` (the rest section's one free word, offset 328),
and the report reads it back: `user fault <pid> cause <c> at 0x<epc>
addr 0x<stval>` — for a page fault, the address the walk never
reached; for the other exceptions, whatever the hardware recorded (an
illegal instruction's bits, or zero). The address is asserted in the
chain where the epc is not: it is the program's own constant, stable
across builds.

Nothing inspects the address to fill a mapping — demand paging is out
of scope by decision, and with it copy-on-write and swap: there is no
consumer of a filled page yet, and a handler that could invent
mappings would be the one component the tables' strictness could not
reach. A fault in S-mode — a miss in the kernel's own table — remains
the machine-wide loud failure it always was; the kernel runs on tables
it built itself, so a supervisor page fault is a kernel bug, never a
process's.

## What this does not yet do

Nothing of Step 6 — the address isolation is closed, pinned, and
accounted. What comes next is M6's own machinery (the virtio-blk
service and the DMA buffers it will ask the allocator for); nothing
in the tables' design is waiting on a decision.

## The pins

- `run.sh`: `sv39 8 0x8…` is the chain's first line under both timer
  transports; the rest of the chain is byte-identical to the pre-T6.2
  chain except two lines — the kill report's cause is 13 (the load
  page fault; the pass's own table maps nothing at `0x80000000`, where
  the pre-table window mapped the firmware's gigapage and PMP answered
  cause 5) and the last line is `frames 17 10` — the four blocks the
  per-process tables' frames split beside the thirteen. The greeting
  (`U-MODE 500500`) rides the gate now — the same bytes, through the
  console service, because the pass's own table maps no UART. Since
  T6.3 the chain is **unchanged again, byte for byte** under both
  transports, three consecutive rounds — the crossing changed, not the
  behavior; the kill report's epc moves per build and is not asserted.
  T6.4 grows the chain: the store-fault pass (`smash`, cause 15, its
  store at `0x40000000` where its table maps nothing) between the
  runaway and the good child, both fault reports name the address
  (`addr 0x80000000`, `addr 0x40000000` — asserted, stable across
  builds), and the last line is `frames 19 12` — the store-fault
  pass's stack and arena beside T6.2's seventeen, its table's frames
  drawn from the splits' leftovers. T6.5 grows it once more: the
  reach pass (`cause 15` again, but the mapping is there without U —
  the permission is what the walk refuses, `addr
  0xffffffc080200000` named in full: a kernel address is negative as
  an `Int64`, and the hex printer is now the 64-bit pattern
  unsigned-faithful), and the DMA proof at the machine's end — `dma
  0x…0000 ok`, the allocator answering one whole 64 KiB block after
  everything the boot took, split, and gave back, one pattern word
  per frame all reading back, the block returned — with the last line
  `frames 23 15` (the reach pass's two, its table splitting the
  fifth table block, and the check's own take-and-give on the
  ledger).
- The kernel could not run at all without translation — its every
  address is a high-half one — so the chain's existence is the proof
  that `satp` is on; the `sv39` line is the proof that the table
  running is the Emo-built one and not the stub's. The chain is also
  the proof the per-process tables work: the greeting, the gate line,
  and the spawn/wait round trip all cross `satp` swaps at the pick,
  and the kill report proves a pass's wild access meets its own
  table's absence, not the machine's RAM. Since T6.3 every user trap
  in the chain crosses the trampoline — the greeting, the gate lines,
  the read's block, the kill, the heap report, and the exit all frame
  at their pass's anchor — so the chain is the proof the crossing
  works end to end.
- QEMU's monitor, `info mem` with the kernel's table live: the seven
  mappings of the kernel's table above — the supervisor's low window
  identity `rw-`, the PLIC and UART high `rw-`, text `r-x` (one page
  longer since T6.3: the trampoline page), rodata `r--`, the image's
  RW head and the high RAM megapages `rw-` — and **not one entry
  carrying U**. The same read of the CSRs: `stvec` names the
  trampoline page's address, **page-aligned** (the section is alone on
  its page), and `sscratch` is 0 while a kernel process runs — the
  sentinel, kept true by every return into either world.
- Watchpoints at the anchor catch the crossing's save landing there:
  the trampoline's store writes the frame at the anchor with
  `sscratch` holding the interrupted user sp, and the swap put the
  anchor into `sp` — the entry obeyed nothing the pass chose.
- Three consecutive smoke rounds, the serial payload byte-identical.
