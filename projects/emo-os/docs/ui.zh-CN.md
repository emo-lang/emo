# 控制台渲染器——EmoUI on EmoOS

机器如何打出它的帧:作为用户趟运行的声明式渲染器——机器唯一的程序,由 shell 的 `counter` 命令启动(T7.5)——它渲染的节点词汇、驱动它的循环,以及它声明出的边界。定案于 T7.4(2026-10-31),趟在 T7.5 从证明链搬到了提示符。它周围:shell([`shell.zh-CN.md`](shell.zh-CN.md))在趟退出后拥有控制台;它说话用的动词是 [`syscalls.zh-CN.md`](syscalls.zh-CN.md) 的;它所镜像的便携核心在 [`projects/emo-ui/`](../../../../projects/emo-ui/)(主树的 [`docs/emo-ui.md`](../../../../docs/emo-ui.md) 是设计本身的常设记录——本笔记把它带到这门语言所启动的机器上)。

英文原文:[`ui.md`](ui.md)。

## 它是什么

EmoOS 上的 EmoUI 控制台后端。一个用户趟构建声明式节点树,渲染器把它排进字符网格,网格经门的 write 动词驶向控制台服务——与内核 `println`、shell 的每个字节同一条路。事件经 read 动词驶回:控制台的按键就是循环的输入,模型改变,树重建,帧重画。这一趟是机器第三种住户——既非内核、也非服务、也非 shell,而是应用——也是闭包演示的最后一件:内核是 Emo,shell 是 Emo,UI 也是 Emo,从 trap shim 到线上那帧,一种语言。shell 的 `counter` 命令按证明链自己的 spawn 纪律启动它——token 单元被 poke、子进程重入镜像顶层、exit 应答 wait——于是全启动的故事读作:上电,提示符,一个用户程序跑起来,文件系统往返。

## 通货

控制台的文本是裸字节。riscv64 后端的 String 表面只有相等——每个 String 方法按名拒绝——所以节点词汇在宿主核心携带 String 的地方携带地址与长度:`Text` 的 body 是镜像读写段里一段字节的地址与长度,启动时从字节数组字面量 poke 进去(shell 的纪律、`shell.emo` 的文本;数组逐元素读进裸内存——任何地方都没有数组元素赋值,目标拒绝它,也不存在可求援的 String 转字节通路)。style 以整格为单位——`Int64`——因为控制台唯一的单位是字符格,半格是它无法显示的东西。

## 脊架

宿主核心的脊架,换上控制台的通货:

- **`Node`**——每个节点都应答的接口:`style()` 与 `children()`。一种树类型,节点与节点才能组合。
- **`Column`**、**`Row`**——容器,一个 `Array[Node]` 的孩子加一份 style。书写时已知的树就是数组字面量;`ArrayBuilder` 不在通路里(目标拒绝其构造——`E2015` 的近邻——脊架里任何东西都不得求援于它)。
- **`Text`**——显示字节的叶:一个地址、一个长度、一份 style。
- **`Button`**——携带事件的叶:一个标签、事件的 tag、一份 style。按钮是事件的载体,绝不是闭包——宿主核心自己的契约,而在这个后端上 tag 是应用的常量(理由见循环一节)。
- 四个小写工厂——`column`、`row`、`text`、`button`——让树读起来像 EmoUI 的树那样读:嵌套调用,`.new` 永不出现在树里。

有意留在宿主侧的:`Align`、`grow`、固定宽高、`Scroll`、`TextInput`、`Image`、`Spacer`。渲染器会无视的携带值是静默回退,没有东西渲染它的节点种类是没挣到位置的构造;每一件都在某一帧需要它、金测证明它的时候再加入。

## 帧

帧是裸内存里 `宽 × 高` 的格网,每行 `(宽 + 1)` 字节——每行最后一个字节是换行,启动时 poke 一次,于是整帧就是**一次 write**过门(暂存上界 2048;帧绰绰有余装下)。每次重画先把格网清成空格(换行列除外),走一遍树,写下格网:线上是 `高` 行、每行恰好 `宽` 字节,行尾空格是帧自己的。越过格网边缘的绘制被裁掉——渲染器的本职、帧自己的上界,不是静默回退。

## 布局

TUI 后端的盒模型,取控制台买得起的那部分格子:列把孩子们向下堆,行把他们向右排齐,`padding` 把容器的孩子四边内缩,`gap` 把他们分开。尺寸全是固有的——叶度量自己的字节(按钮多两个,渲染器画在标签两侧的方括号),容器度量孩子加上自己的 padding 与 gap——然后走一遍树,把量好的放下。没有拉伸,没有居中,没有滚动:上面的词汇就是这一帧用到的,算术就是 TUI 的,减去控制台没有消费者的那些部分。

## 循环

Elm 循环,类型化的。一个 model,一个纯 `update(model, tag)`,一个纯 `view(model)`——三个函数,控制台的事件源坐在循环的座位上:read 动词来的一个阻塞字节,由应用映射成一个 tag,tag 过 `update`,model 过 `view`,树过渲染器。重画是整幅的——TUI 自己的决定(终端从不 diff,`patch` 的旧树是它从不需要的提议)——所以宿主循环的 tag 注册表留在宿主:整幅重画不需要 tag 稳定,tag 是应用的常量,按钮的 event 就是其中之一。控制台的按键按应用自己的规则映射到 tag——哪些字节是它的事件由应用决定,**未映射的字节被丢弃,从不去猜**(shell 行规程的规则,搬过来)。什么都不回显:帧就是应答。

循环在自己的一个 tag 上结束——应用的 quit——如同 TUI 的运行循环在输入耗尽时结束。随后是趟的退出:引导趟的 exit 动词,由父进程的 wait 应答,之后是 REPL 的提示符。

## 演示——计数器

金测跑的那个应用:计数器,Elm 架构自己的例子,放到控制台的尺度上。帧 32×8,根列 padding 一格、gap 一格:

    (空行——padding)
     EmoUI on EmoOS
    (空行——gap)
     count 000
    (空行——gap)
     [a plus]  [b minus]  [q quit]
    (空行——padding)
    (空行)

`a` 与 `b` 是模型的事件(加与减,计数夹在 0 与 999 之间——三个数字格,每帧之前重 poke,树引用固定单元),`q` 是循环自己的。按键经 read 动词一次一个;帧经 write 动词每次一整幅。

## 边界

- **趟的 arena 是 64 KiB,收集器不存在。**树按事件重建,没有东西回收;演示的会话就是金测的那三个键,对着这份 arena;永远画下去的会话就是耗尽击杀——每个用户趟共有的生命周期上界,在这里说出来,因为这个循环的全部工作就是重建没有东西释放的东西。
- **渲染器运行期间独占控制台。**一次一个读者是控制台服务的最老请求纪律(T3.7):REPL 在趟的第一次读之前停进 wait,趟退出后重新出提示符——喂数排在退出键之后的字节都是 REPL 的,FIFO 顺序就是全部交接。
- **帧在自己的边缘裁剪。**格网是渲染器作画的全部世界;比帧宽的树,多出的字节由帧的上界收走。
- **内核零改动。**门路由的还是 T4.2 以来就路由的 read、write 动词;整个任务都在用户侧、`run.sh` 和本笔记里。

## 钉子

`run.sh` 的链条把趟的对话放在 REPL 的第一个提示符与 shell 的文件系统往返之间,双定时器传输皆是:线上的 `counter` 命令、趟一被 spawn 第一帧就在——标题行、计数的 `000`、按钮行——第一个键之后 `count 001`,退出键结束趟(它的 exit 应答 shell 的 wait,第二个 `count 000` 不断言——首次出现已经证明了帧),然后提示符回来,机器的前台继续,往返在其后骑行。每条腿三轮逐字节相同;帧账目长出趟的栈与 arena——spawn 时取走,退出时归还。
