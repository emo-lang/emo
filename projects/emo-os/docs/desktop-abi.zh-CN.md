# 桌面协议的稳定性契约

门的动词编号已由规矩冻结([`syscalls.zh-CN.md`](syscalls.zh-CN.md)):一个编号一经分配,含义永不再变——只增不改,版本化承载其余。桌面段(**动词 10..16,预留:`present`、`output_info`、`input_read`、`win_new`、`win_close`、`win_focus`、`win_move`**)把这条规矩从编号扩展到整个协议面,因为桌面的协议活得比它的每一个实现都久——Wayland 与 Quartz 是证明,win32k.sys 是反例。

本文档是桌面([`projects/emo-desktop`](../../emo-desktop))在其内生长的契约。完整调研记录、每个接缝背后的推理,在[桌面评估](../../emo-desktop/docs/assessment.zh-CN.md)。

## 三层

- **Tier A——协议 ABI,冻结。** 动词编号、事件流形状、capability 模型。破它们就是破掉每一个写过的应用;冻结编号规矩是机制,版本化本身就是契约的一部分。
- **Tier B——实现,可搬。** 字体可以变 TrueType,blit 可以变 GPU 工作,合成器可以离开内核镜像成为用户进程——不动一个动词、一个事件的形状。搬不动的实现,是协议围着它设计的实现——win32k.sys 的病。
- **Tier C——追加。** IME、剪贴板、截屏、通知、无障碍:新编号下的新动词与新事件,永不是对旧者的改写。

## 八个接缝——从第一个动词起就对

1. **缓冲是 capability 对象**,永不是裸物理地址——IOSurface/DMA-BUF 形状。门的授权表按 grant 名缓冲、不按地址;这是 GPU 路径、零拷贝、沙箱的前提,且无法事后补上。
2. **outputs 列表不是常量。** `frame_w`/`frame_h` 式常量是诚实的陷阱;协议枚举 outputs——`output_info` 是它的动词——一块屏是第一个答案,不是唯一的形状。
3. **surface 带 role 字段**——toplevel/popup/subsurface/panel。先实现 toplevel;其余按名拒绝,不靠沉默。
4. **format 与 scale 是字段**——XRGB8888 是第一个被接受的值,协商的形状从第一天就在。
5. **统一版本化事件流,带 frame callback。** virtio-gpu 无 vblank;合成器按 tick 合成,frame callback 是动画故事的命门——真硬件到来时,保节奏诚实的接缝。
6. **present 是原子 commit。** 一帧的状态整体落地;没有动词看得到半 present 的一帧。
7. **文本永不进协议。** 键与字形是两端的事;合成器运字节与矩形,永不运字符串——让 IME(Tier C)可以追加而非改写的接缝。
8. **机制与策略分离,合成器可回缩。** grant 对象从第一天起可 attach 进任意授权进程表,于是合成器可以离开内核镜像(Tier B)而协议毫无察觉。

## 表面与其角色(T8.13,emo-desktop A9.1)

第三接缝的落地:缓冲在其客户端为它声明角色时成为表面——动词 17,
`win_role(grant, role)`——合成器的栈只对表面行动。词表冻结:0
toplevel、1 popup、2 subsurface、3 panel。合成器实现的角色是
toplevel;其余三个按原因 4 拒绝,按**它们的号码**——协议不携带
文本(第七接缝),选了角色的调用者才是把它说出来的人(线上的
`role popup r4`)。表面的角色不变;第二次声明按拒绝处理。栈条目
携带 grant、位置与角色;`win_focus` 把它抬到栈顶,`win_move`
安置它,窗口 present 投递的合成是整条栈自底向上、走过一块清成
合成器自己背景的 carve——最后一个条目压住其余,挪走的窗口旧位
重新成为背景,每个 ready 行所在的表面都被搬走,正在呈现的客户端
的应答在 flush 之后(第六接缝)。线上每次合成为 `comp <x> <y>
<sum>`——正在呈现的表面的位置与走栈搬过去的字。客户端缩放流的
绝对报告的量程是设备自己的回答,动词 18,`input_info(index)`——
第二接缝的输入侧;输出的枚举有了它的孪生。

## 光标平面的精灵内存(T8.11,emo-desktop A8.2)

指针的精灵是桌面侧的——Wayland 客户端的光标归客户端,这一个同样如此:合成器运像素与矩形,永不运一张画。契约是内存,不是动词。screen carve 的最后 64 KiB 是光标平面的精灵内存;越过块的首行——screen pass 的证明字样往 carve 每 64 KiB 的首字 poke 一词,这块也在内——桌面侧(持有 carve 映射的全屏 pass)写入:

- `+64` 头部,四个 32 位字:宽、高、热点 x 与 y(以精灵像素计);
- `+80` 像素,宽 × 高个 ARGB8888 字,行主序,顶字节 0xFF 为不透明、0 为透明,至多 64 × 64;

头部最后写,于是撕裂的读看到的是"无精灵":宽为零即合成器的尚无精灵,平面在桌面画出之前什么都不合成。save-under——被画中的精灵盖住的 carve 像素,合成器自有的半块,在 `+0x8000`——是内核私有的,不在契约之内。合成器在每次合成时读头部,在每次窗口 blit 前后藏起精灵(save-under 里永不留旧词),按指针位置移动它,并把新旧两处同框的矩形 present 上屏。光标动词仍可能加入桌面段(Tier C,只增);无论加不加,这份内存契约都成立。

## 契约救不了的——诚实的四件

arena 的残留(autorelease pool 作为 Elm 循环的前置已经落地,循环也跑在它上面了,emo-desktop A8.3——现在给一次会话划界的是动态约定里装箱的数字,每帧每节点约 3 KiB、每字形约 600 字节,下一件是类型化的方法体)、协作式单 hart(抢占必须落地;`-smp` 是 parked 不是不可能)、单镜像多 pass(M11 自己的活)、泛 IPC(portal 类服务终会要;实测路径要它时再造)。没有一件是协议变更;四件都是机器侧与语言侧的活,记在本项目的 Step 8。
