# 弱隔离窗口

窗口存在期间——用户程序与内核共享一张平坦物理地址空间时——U-mode 能与不能够及什么,以及是什么关上了它。窗口随 user profile(T4.1)开启,随 SV39 的每进程页表(T6.2)关闭;本文档是它的常设记录,够及范围是有账可查的事实,不是口口相传的传说。T4.5(2026-10-27)定案,T6.1(2026-10-29)更新——窗口变成内核自己那张表里的一个映射,T6.2(2026-10-29)关闭——每个用户进程跑在自己的页表上,窗口的表项不复存在——T6.3(2026-10-30)再行加固——trap 入口也不再服从用户的 `sp`。内核的地址空间布局另有文档:[`sv39.zh-CN.md`](sv39.zh-CN.md)。

英文版:[`isolation.md`](isolation.md)。

## 路线

特权先行,地址空间后置——既定的隔离路线。用户程序在分页存在之前一个里程碑就以 U-mode 站到 ecall 门后面,因为门与门背后的东西——supervisor 的参数检查、拷贝语义、每进程记账——才是永久契约,SV39 随后把它们的强制执行搬进硬件,契约本身一字不动。窗口就是代价:M3 到 M5 之间,隔离是有效的,却不是被强制的,两者的差别写在本文档里,绝不遮掩。

## 内存图

一张平坦的图,每个地址都是物理地址。QEMU `virt` 的 128 MiB RAM 里有什么,以及旁边的 MMIO:

| 范围 | 内容 |
| --- | --- |
| `0x80000000`–`0x80200000` | OpenSBI(M-mode)——唯一被 PMP 锁住的区域 |
| `0x80200000` | 内核镜像——text、rodata、data,以及装着 96 MiB 值堆(根进程的 arena)、64 个进程槽、64 × 64 KiB 绿色进程栈的 `.bss` |
| 镜像末尾–`0x87000000` | 帧分配器的区域(T5.3)——镜像之上的空闲 RAM,向上取整到块,按 64 KiB 块(十六个 4 KiB 帧)分发:每个 spawn 出来的进程的 arena、每个用户进程的栈、内核与每个进程的页表(T6.1/T6.2) |
| `0x87000000` | tick 环(`.emo_tick`) |
| `0x87001000` | 输入环(`.emo_in`) |
| `0x87002000` | 用户交接页(`.emo_user`)——内嵌镜像的界址、stage 出的入口、段表、stage 出的 space cell(T6.2) |
| `0x87003000` | 帧分配器的页(`.emo_frames`)——freelist 头、空闲与总块数、区域界址、认领位图、帧 freelist |
| `0x87004000` | Sv39 页(`.emo_sv39`)——内核的根表、活的 `satp`、切换的缓存 |
| `0x87100000`–`0x88000000` | 用户窗口——每个用户镜像链接在它的基址 |
| `0x10000000`、`0x0c000000`、… | MMIO——16550A UART、PLIC、`virt` 的其余设备 |

窗口存在的岁月里(T4.1–T6.1),用户以物理地址本身够及这张表的每一行——T6.1 之前不经翻译,之后经内核表里窗口的两条 U 巨页表项。自 T6.2 起,内核的表不再携带任何 U:内核够及它的半区与监管者的低位窗(`0x80200000`–`0x88000000`,恒等,无 U——装载器的拷贝、交接 cell、往停放的 trap 帧里写的答案),而每个用户进程够及的恰是它自己的表所映射的东西([`sv39.zh-CN.md`](sv39.zh-CN.md)——带 U 的镜像各段、它自己的栈与 arena、cell 页,以及无 U 的内核高半区)。

## U-mode 能够及什么

- **它自己的页,再无其他。** 镜像的各段——代码 RX、数据 RW(一个镜像的各 pass 共享它们:spawn 出来的 pass 重入顶层,找到父进程 poke 的 token)——它自己的 64 KiB 栈块与 arena 块,以及 cell 页。内核的半区映射在同一张表里但无 U:为 trap 而在,U-mode 够不到——boot pass 的 trap 页(`0x87ffe000`,T6.3)以同一份契约加入,那一页 scratch 不属于任何执行的记忆。其余每个地址都是一次缺页,supervisor 为此响亮地击杀肇事的 pass。
- **raw 家族按 target 准入,不按 profile。** `peek`/`poke`、`ecall`、`device_wait` 在用户镜像里是合法拼写,按准入自身的原则——一个 target 准许 raw 家族,当且仅当程序拥有地址空间。自 T6.2 起,这条准许在两个方向上都诚实:拼写只够及该 pass 自己的页(其余一切是缺页),而内核自己的服务用的词汇(`user_spawn`、`gate_reply`、`pid_num`)仍在表层拒绝之处拒绝。第一个用户程序的问候在窗口存在时骑的就是这条准许——它直接 poke 16550A,`run.sh` 钉住那一行。自 T6.2 起,pass 的表不映射 UART,问候改走门,线上字节不变。
- **门是被认可的门。** 来自 U-mode 的 `ecall` 永远 trap 进内核的 shim——从不进 OpenSBI——诸动词都骑在它上面。门拒绝的东西作为答案拒绝:调用者的寄存器原样往返,执行在 `ecall` 之后继续。write 的字节由检查范围的那同一个 trap 拷进内核的暂存页(T6.2)——service 读的是内核的拷贝,从不读调用者的内存。

## U-mode 够不到什么

- **它的表不映射的一切,以及一切无 U 映射的东西。** 内核的内存、其他进程的栈与 arena、分配器的页、页表本身、两个环、设备——每一处都是缺页(cause 12/13/15)或硬件的权限拒绝,而 supervisor 响亮地击杀肇事的 pass(`user fault <pid> cause <scause> at <epc>`——击杀金测的 cause 如今是 13,load page fault;窗口的 RAM 巨页让同一访问由 PMP 答 access fault,cause 5)。来自内核自己代码的故障仍旧是终结机器的响亮失败——那是内核的 bug,不是用户的。
- **特权指令。** 每个 S-mode CSR(`satp`、`sstatus`、`stvec`、`stimecmp`)、`sfence.vma`、`sret`——U-mode 里的非法指令,同一种被圈住的击杀。
- **固件。** 来自 U-mode 的 `ecall` 是内核的门,不是 OpenSBI 的;固件自己的区域不在任何映射里(监管者的低位窗始于加载地址,T6.1 的决定保持),而 PMP 在一切背后,仍是连 supervisor 都被拒的那段范围。
- **门拒绝的一切。** 集合之外的动词、调用者各段之外的指针、缺该访问所需权限的段——每一个都是经门答回的编号拒绝,不是故障,不是崩溃。

## 什么在防守什么

- **指令特权**——硬件的唯一一条线,它绝对成立:U-mode 无法给自己升权。
- **每进程页表(T6.2)**——窗口的关闭:野地址在成为写入之前先成为故障,击杀圈住进程,因为故障圈住了访问。门做的检查如今有了它们所描述的映射作后盾。
- **门的 supervisor 检查。** 每个指针实参都对着装载器 stage 本镜像时停放的段表查过(每个 `PT_LOAD` 的范围与 ELF `p_flags`):整个范围 `[buf, buf + len)` 必须落在**一个**段内——跨段的调用被拒绝,不被拆开——且该段必须带着该访问所需的权限(`write` 需要 `W`)(契约见 [`syscalls.zh-CN.md`](syscalls.zh-CN.md))——并且字节在门处跨越,在检查的同一个 trap 里拷入,于是没有任何内核进程会在事后反引用调用者的内存。
- **拷贝语义。** 消息在 send 时快照,记在发送者的账上:被腐化的进程无法经邮箱给别家的对象起别名。
- **trap 圈禁。** 用户故障杀死它的进程,不伤其他;内核自己的故障仍是全机器的,理应如此。自 T6.3 起,trap 入口本身也不再服从用户:trampoline 把每一次用户 trap 都铺在 pass 的锚上——内核选定的内存,不是 pass 的 `sp`——于是 pass 无法靠移动栈指针来瞄准内核的帧写入,而分派跑在内核自己的表和栈上,隔着入口在过渡中完成的一次 `satp` 换手(见 [`sv39.zh-CN.md`](sv39.zh-CN.md) 的 trampoline 一节)。
- **每进程记账(Step 5)**——arena、配额与帧分配器:每次分配记在正在运行的进程自己的 arena 上,一个跑飞的进程独自耗尽自己的 arena,而进程持有的每一块——它的 arena、用户进程的栈——都是内核帧分配器的,spawn 时取走,死亡时归还。
- **PMP**——固件的区域,唯一一段连监管者的低位窗都不映射的范围。

## 窗口为何曾被接受

在时间上与种类上都有界,而且如今已关闭。时间上:SV39 在固定路线图的一个里程碑之外关上了它,而这次关闭没有挪动门一直在强制执行的契约。种类上:长期要紧的防线本来就是软件契约——一个守在自己段内、凡事走门的用户程序,从门发布的第一次起事实上就是隔离的,因为门检查一切跨越的东西,拷贝让进程无法互相起别名。窗口留着没有强制的,恰是野地址的够及,而每进程表在不挪一个动词、一个理由码的前提下,除掉了这一整类错误。够及范围在其存在的岁月里有账可查;什么都不假装。
