# Shell——控制台与文件系统之上的 REPL

EmoOS 如何收尾启动:引导证明结束后接管机器前台的那个 REPL 进程,它读取的行、应答的命令,以及它声明出的边界。定案于 T7.3(2026-10-31)。它下方是门所路由的那两个服务——控制台服务(T3.7/T4.4)与文件系统服务(T7.2,设计见 [`fs.zh-CN.md`](fs.zh-CN.md));它说话用的动词是 [`syscalls.zh-CN.md`](syscalls.zh-CN.md) 的。

英文原文:[`shell.md`](shell.md)。

## Shell 是什么

shell 是一个**用户进程**——用户镜像自身的引导趟(boot pass)。引导证明(gate 行、echo、文件系统往返、四趟被杀的进程、spawn/wait 往返)是顶层的序言;序言结束时,顶层不再退出,而是调用 REPL 循环,机器从此不再自己结束:REPL 就是前台,离开它的方式是 `poweroff` 命令——引导趟的 exit 动词,与证明还是整个程序时结束机器的是同一条路由。

shell 做的每件事都过门:它打印和读到的每个字节都经 write、read 动词穿过控制台服务,每次文件操作都经文件系统动词穿过文件系统服务。shell 就是 U-mode 里、自己的地址空间上的普通类型化 Emo,只说 `syscall` 包的桩——机器里第一个既非内核也非服务的住户,也是「用户侧与底下那个监督者同为一种语言」的常驻演示。

REPL 和每个用户趟一样在引导趟的 arena 里分配,收集器尚不存在:上界就是用户堆(8 MiB),每次交互几十字节,与每个用户趟共有的生命周期上界相同。

## 行

控制台是裸字节——shell 之下没有行规程——所以 REPL 自己搭行,一次一个字节,每个字节都是一次过门的阻塞读:

- **可打印 ASCII(32–126)**加入行内并回显——终端看见自己敲的字,因为除此之外没有任何东西回显。
- **退格(8)与 DEL(127)**抹掉行的最后一个字符,回显三字节序列 `\b \b`;空行上什么都不做。
- **CR(13)与 LF(10)**都结束行,回显为单个 LF——内核自己的控制台规程(`println` 写裸 LF,shell 的输出跟着走)。
- **其余字节一律丢弃**,本笔记明说:shell 不去猜一个控制字节是什么意思。
- **行上界 120 字节。**越界的字节被丢弃*且不回显*——缺掉的回显就是痕迹,与 gate 暂存上界同一种严格(那边是 reason 4,这边是看得见的沉默)。

提示符是 `emo> `,每读一行之前打印。

## 命令

行的解析只有一条规则:跳过行首空格,命令词到第一个空格为止(或行尾),其后隔一个分隔空格的内容就是参数——逐字保留,空格在内。命令小写、精确匹配。共七个:

| 命令 | 参数 | 效果 | 输出 |
| --- | --- | --- | --- |
| `help` | 无 | — | 一行列出七个命令 |
| `echo` | 文本,逐字 | — | 文本加换行;空参数就是空行 |
| `ls` | 无 | `file_list` | 名字,一行一个,按服务列出的样子;空卷什么都不列 |
| `cat` | 一个名字 | `file_read` | 文件字节加换行;读的容量是 2048,即写上界,所以整个文件总是装得下 |
| `write` | 一个名字,然后文本 | `file_write` | 该名字的文件变成文本的字节(没有文本就是空文件);成功时安静 |
| `rm` | 一个名字 | `file_remove` | 文件消失;成功时安静 |
| `poweroff` | 无 | 引导趟的 `exit` | 机器结束——exit 路由的 `dma` 行与 frames 账目,然后 SBI 断电 |

严格性是平台的,一路带到表面上:

- 不带参数的命令拒绝参数(`ls foo` 应答 `ls: bad argument`)——没有东西被悄悄忽略。
- 带一个名字的命令拒绝第二个名字,也拒绝没有名字,同一行字。
- 不认识的词应答 `<词>: unknown command`。
- 空行(或全是空格的行)什么都不应答,重新出提示符。

文件命令成功时安静,因为安静是 Unix 惯例教的,而金标准通过下一条命令证明效果(`ls` 看见 `write` 写了什么;`rm` 由它之后拒绝的 `cat` 证明)。服务应答的每一次拒绝都回来一行,`<命令>: <消息>`,消息是 `syscall` 包起的名字——`no such file`、`bad argument`、`the kernel is out of a resource`。

## 错误消息

桩把拒绝应答为 `(R.error, why)`,`why` 是 String,而 riscv64 后端的 String 表面只有相等比较——后端按名字拒绝每一个 String 方法。所以 shell 用字符串相等把消息映射回来(证明链里 `reason_num` 的形状)再打印自己的字节:文件动词可能应答的四条消息在 REPL 启动时戳进 shell 的暂存区,除此之外的一切打印为 `refused`。对一个缓冲区都在自己可写段里的 shell,这张映射对桩可能说出的话是全覆盖的。

## 暂存区

shell 在用户镜像的读写段里持有自己的地址,在证明链的上方(loader 清零、gate 检查的那一段——ELF 的 RW 段比这些地址多出若干兆字节):

| 地址(自暂存基址 `0x87200000` 起) | 内容 |
| --- | --- |
| `+6144` | 行,128 字节(上界 120) |
| `+6272` | 列表缓冲,256 字节 |
| `+6528` | 读缓冲,2048 字节 |
| `+8576` … | 文本:四条拒绝消息、`unknown command`、help 行、提示符、七个命令名、`: `、一个 LF——REPL 启动时从字节数组字面量一次戳入,是 shell 打印的全部文本 |

文本走字节数组字面量,因为字符串不行:riscv64 后端没有 String 转字节的通路,而「数组字面量逐元素读入裸内存」就是诚实的写法。其中没有数组元素赋值(目标拒绝它):数组是被读的一方,目的地是裸内存。

## 边界

- 命令集就是上面七个。启动程序不在其中——闭包演示(T7.5)会决定程序如何从 shell 开始,若挣得一个词,命令集那时再长。
- 一卷、平面名字空间、整文件:文件系统服务自己的上界(T7.2)。带空格的名字对服务合法、对 shell 不可达——空格是分隔符。
- 无旗标、无路径、无环境变量、无作业控制:控制台就是整个世界,行就是全部输入。
- REPL 就是引导趟,它的退出就是机器的结束:没有可以返回的 shell,因为 shell 就是最后在跑的东西。
- 一次一个读者,控制台服务的最老请求纪律(T3.7):证明链的读者在 REPL 开始前都已结束,REPL 的读和写从不与其他客户的事务重叠。

## 引脚

`run.sh` 的链条在证明链最后一行之后长出 REPL 的这段对话,两种定时器传输下都有:第一个提示符、`help` 行、echo 命令的回显、`ls` 列出 `hello.txt`、`cat boot.txt` 念出内核引导文件的字节(`EmoOS boots from disk`,由内核根经第一个实例写入——用户程序经门把盘上的内容读回来,测试没有代劳任何 staging)、`rm` 之后的拒绝 `cat: no such file`,以及 `bogus: unknown command`——然后是 exit 路由的各行,如今由敲下 `poweroff` 抵达。写由列表上的行序检查证明:第二次 `ls` 在相邻两行应答 `hello.txt` 与 `note.txt`,而写的回显变不出这一对。每条腿连续三轮逐字节相同。
