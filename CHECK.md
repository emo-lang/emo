# CHECK

Pending design decisions — deliberately kept out of the README until they are settled.

- Mixin mechanism: include syntax, single vs. multiple includes, name-collision rules.
- Exception catching syntax (`raise` is decided; the catch form is not).
- Whether raw strings are needed. The escape set settled in step 12: `\n \r \t \\ \' \"`.
- Numeric literal formats: hexadecimal, binary, digit separators (decimal-only for now).
- Numeric width: **settled** — numeric types are width-explicit: `Int64`/`Int32` and `Float64`/`Float32`; defaults are `Int64` and `Float64`; no width-less `Int`/`Float` spellings; bare literals default to the 64-bit type (decided 2026-10-05 — README, Type System; rationale in `docs/numeric-width.md`). Open: the native backend's route to 64-bit integer arithmetic on OCaml's 63-bit `int` — emit OCaml's boxed `Int64` vs unboxed two-word hi/lo emulation (the technique RV32 codegen will also need). The mechanical `Int` → `Int64` / `Float` → `Float64` rename across checker/stdlib/examples/docs has landed.
- Int32 / Float32: agreed as future explicitly-named fixed-width types for FFI (`int32_t` / C `float` marshaling), bare-metal MMIO/device registers, and RV32 hot loops (`docs/numeric-width.md`). Open surface: explicit-only conversions, per-type wrap/rounding (literal typing settled — bare literals are `Int64`/`Float64`).
- `foreign def` on non-native targets: wasm and BEAM may compile foreign calls into silently broken code today. Settle the rule — every target that cannot honor `foreign def` refuses loudly at check time, with per-target availability declared through the manifest's `targets` mechanism. Gate before any FFI deepening (step-14's RISC-V reference note).
- C FFI binding-surface syntax: **settled in step 13** — `foreign def name(params) Ret = "c_symbol"`, `Float64`/`String`/`Bool` only, compiled through generated C wrappers (see `docs/native-backend.md`).
- Self-contained hosted native backend (no OCaml runtime): **assessed, not scheduled** — `plan/step-23-hosted-native-ffi.md` (recorded 2026-10-06). Three decisions gate it: (a) the codegen route (**recommended: emit C**, over LLVM IR and hand assembly), which fixes the tail-call strategy — C does not guarantee TCO and Emo's only loop is tail recursion; (b) reclamation without a tracing GC (reference counting vs bounded arenas with explicit leakage, and whether either needs a language-surface addition — Emo has no ownership/region annotations by philosophy); (c) the HPC surface — in priority order: vectorization/SIMD, a data-parallel construct, zero-copy FFI buffer passing (`Buffer[Float64]`, borrowed for the call), and ecosystem. If taken, this backend supersedes the open item above on the native backend's route to 64-bit integer arithmetic on OCaml's 63-bit `int`.
- Codegen route for a self-contained native backend: **recommended — emit C**, with LLVM ruled out (C++ dependency, unstable API, opaque generated code, against the "emit and delegate" / readable-output line) and hand assembly confined to the freestanding `riscv64` target. Emitting C reuses the existing `cc` dependency, yields GCC/Clang autovectorization and OpenMP pragmas, and makes the C ABI the FFI surface. The emitter must own explicit tail-call lowering (trampoline / block-loop), wrap-around `Int64` (unsigned arithmetic or `-fwrapv`), `restrict`-annotated vectorizer-friendly loops, and the dynamic layer (tagged unions plus `retain`/`release`; exceptions via `setjmp`/`longjmp`). See `plan/step-23-hosted-native-ffi.md`.
- Reclamation model for the dynamic world without a tracing GC: reference counting (no stop-the-world; fits Emo's value semantics; the Swift / Objective-C lineage) vs bounded arenas with explicit leakage. Either way the specialized numeric tier needs no management, so the decision is scoped to the dynamic, escaping, and message-passing paths. Whether the chosen model requires a language-surface addition is part of the decision.
- HPC criteria for the self-contained backend, **in priority order**: (1) vectorization/SIMD — the codegen route must deliver it (emit C, not LLVM or hand assembly); (2) a data-parallel construct (OpenMP-style parallel loop with reductions); (3) zero-copy FFI buffer passing — a mutable, address-stable, typed buffer (`Buffer[Float64]` or equivalent) borrowed for the call, per the `cgo` model, since `Array` is immutable and `Bytes` is byte-addressed; (4) ecosystem. GC is a latency and predictability concern (headroom, jitter), not the gate. Reference sample: Go — GC + custom backend + `cgo`, still not an HPC language because it does not autovectorize and has no parallel-loop primitive.
- Binary / CLI tool distribution mechanism.
